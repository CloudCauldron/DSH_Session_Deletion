# DSH 会话删除与附件清理

版本 **0.3.6**。适用于 **DeepSeek Harness 0.2.1-rc.5 / Linux glibc / 默认 Web profile、JSONL 和本机附件存储**。
TypeScript 开发，运行只需要 Node.js（≥24.9）及自动安装的 `koffi`，不需要 Python。

## 两个独立操作

| | 会话删除 | 清理残留附件与缓存（GC） |
|---|---|---|
| 入口 | 会话行 `…` 菜单最底部，红色「删除」或「归档并删除」 | 侧边栏「更多」→「清理残留附件与缓存」 |
| 准入 | 只检查目标会话及其子代理；其他会话可继续 AI、工具、后台工作和上传 | 所有驻留会话、Agent、后台任务和终端空闲；等待已进入服务的提交、日志及投影写入完成 |
| 日志 | 删除目标及递归子代理的私有目录 | 保留全部会话日志 |
| 登记 | 清目标的工作区成员、归档、置顶、投影缓存和绑定的定时任务历史 | 保留会话登记 |
| 附件 | **不扫描引用，不删除任何附件、文件名链接或图片请求缓存** | 扫描所有存活会话的完整日志、未发送上传和存储引用，删除无引用对象与文件名链接 |
| 其他文件 | 保留项目文件、独立分叉和所有临时输出 | 保留项目文件、临时输出及有引用的附件；清空可重建的图片请求缓存，移除未引用的残留附件的本机上传映射 |
| 输入 | 只锁目标及子代理；其他会话仍可接收输入和上传 | 清理期间新服务提交短暂排队；直接同步后台发布会明确拒绝，稍后可重试 |
| 中断 | 恢复已提交的私有删除清单 | 保留已经完成的回收；再次手动执行时重新计算引用，不重放旧垃圾清单 |

两个菜单入口复用 DSH 原生 `MenuItemButton` 与 SVG 图标，沿用原生字号、悬停和禁用样式。删除按钮带原生危险色和分隔线。

会话删除与 GC 确认弹窗均复用 DSH「停止并归档此会话？」使用的原生 `Modal` 和 `Button`，说明正文通过 `description` 属性排版，沿用原生字号、行高、间距、圆角、遮罩及焦点管理。

状态通知使用工作区同款原生 `Toast`，取代旧的左下角自绘提示框，位置沿用 DSH 默认的顶部居中。删除时显示「正在删除会话…」，GC 时显示「正在清理残留附件与缓存…」。中断后显示带原生警告图标的「清理未完成，将在下次启动时自动恢复」；服务端会区分正在执行与待恢复事务，避免正常删除被误报为中断。

通知沿用原生显示和淡出动画，进行中提示使用默认时长，待恢复提示停留 8 秒后淡出；相同状态的轮询不会重复弹出。通知消失不解除输入锁，控件可用状态仍以清理是否结束为准。

## 会话删除

选择菜单项后，弹窗依次显示操作标题、加粗的会话名称、等宽字体的会话 ID，以及「该会话的全部记录将被彻底移除且无法找回，已保存的文件与附件不受影响。」仅当存在子代理时，在「无法找回」后补充「（包含与该会话关联的 N 个子代理）」。取消按钮统一为「取消」，确认按钮按归档状态显示「确认归档并删除」或「确认删除」，无需勾选确认框。

预览加载时显示「正在检查会话状态…」。若打开弹窗后会话进入运行状态，显示「会话正在运行，暂时无法删除」并禁用确认按钮。

未归档会话先调用原生归档；归档失败或目标仍在工作时拒绝删除，不强制取消任务。已归档会话仍需要最终目标活动核查。归档成功后若核查失败，会话保持归档。提交删除后，弹窗按钮禁用，直至请求结束。

执行时仅锁目标 ID，复用 `AgentHandle.dispose()` 释放目标对象和写入句柄，取得目标文件锁，删除私有数据。只枚举会话目录和读取头部以确定子代理及目录身份，不扫描其他会话的消息或附件引用；其他会话有损坏的消息正文，也不会因此阻止这条私有删除。公共项目目录不删除，以免影响另一个会话创建日志。

“即时”表示不等退出、不等其他会话结束；仍需要目标资源释放和磁盘 I/O，不承诺恒定耗时。删除不能与正在执行的 GC 或另一条删除同时进行。

浏览器清理只处理目标所属的会话、右侧栏、任务标签存储键，以及明确的导航 ID 字段；不递归改写其他草稿。要求 localhost 或 HTTPS 提供 Web Crypto；离线页面在下次连接时清理。

## 清理残留附件与缓存

确认弹窗标题为「清理残留附件与缓存？」，说明为：「将移除无关联的本地附件及临时图片缓存以释放空间，操作期间请确保其他会话处于空闲状态。」点击「开始清理」执行，或点击「取消」返回。执行中显示「正在清理残留附件与缓存…」。

清理完成后移除确认标题、说明和操作提示，只显示「共清理 X 项残留附件与缓存文件。」以及「关闭」按钮；没有可回收内容时显示 0。合计按附件 ID 去重（对象、文件名链接及上传索引不重复计数），再加实际清理的图片缓存文件数。

GC 执行期间，弹窗所有按钮（含右上角关闭按钮）均禁用，点击遮罩或按 Escape 也不能关闭；弹窗外的会话控件保持锁定。完成或失败、确认服务已结束清理后恢复操作。

GC 是手动维护操作，不会随删除、退出或重启自动执行。确认后取得全局发布屏障：等待已开始的输入和上传完成，核查所有驻留会话的原生活动、`whenIdle()`、队列和终端状态，并刷完原生日志写入及已跟踪的投影写入。仍在生成的图片请求缓存会使 GC 拒绝。其他会话的未来定时提醒不会仅因存在就阻止 GC。

然后扫描所有存活会话（包含归档、独立分叉及保留的日志格式代际），并合并未发送上传及持久化存储中的引用。即使附件尚未进入消息记录，只要有原生上传收据，也会被保护。除 `sha256:` ID 外，日志中的标准附件对象/文件名链接路径也作为保留依据。

清理范围是 `<DSH_HOME>/attachments/v1/` 下的 `objects`、`file-objects`、`files`，以及 `cache/attachments/request-images/` 和未引用的残留附件对应的 `llm-deepseek/files-v3.json` 本机映射。不会向远端服务商发送删除请求。内部保留分类统计，前端仅展示合计数量。

损坏或截断的日志、未知存储格式、符号链接或不符合默认附件布局的数据会阻止 GC，不把无法读取的引用当作不存在。预检先于删除；若执行途中 I/O 失败，可能已经回收部分垃圾，下一次重新扫描即可继续。未知格式应先调查，不能简单忽略以强行清理。

## 安装

```bash
pnpm install
pnpm build
dsh plugin --profile web add "file:$PWD"
```

Web profile 的 `pnpm-workspace.yaml` 需保留原有配置并允许 `koffi` 的安装脚本：

```yaml
allowBuilds:
  koffi: true
```

安装后重启 DSH。插件运行使用 `lib/` 编译产物；`koffi` 只用于调用 Linux 内核文件锁。

```bash
dsh plugin --profile web remove dsh-session-deletion
```

DSH 升级前先完成待恢复删除并卸载插件；此实现精确绑定 rc.5 的生命周期和存储接口，版本不符时拒绝放行。

## 恢复与边界

默认状态目录为 `~/.dsh/session-deletion/`，随 `DSH_HOME` 改变：

- `pending/` 保存 **schema 3 私有删除清单**，不含附件或临时文件清理计划。
- `receipt.json` 保存已删 ID 的哈希及完成数量，防止删除后重新输入并供浏览器清理。
- `status.json` 是最近的删除恢复状态；`gc.json` 是最近一次成功 GC 的统计。
- 单个监测进程持有生命周期锁，确认宿主退出后只恢复未完成的会话删除，然后退出；没有待恢复事务时也会退出。

```bash
# DSH 关闭后，恢复已提交的会话删除；不会执行附件 GC。
node lib/guard.js "$HOME/.dsh"
```

强杀或断电后，下次启动先恢复私有删除。恢复验证目标目录身份，损坏的目标头部或异常路径仍可能阻止恢复；保留 `pending/` 并修复原因后重试。旧 schema 1/2 请求可能含附件清理意图，因此新版拒绝重放，不能只改 schema 绕过校验。升级前应完成或审查旧事务。

支持范围不包含绕过插件直接修改同一数据目录的 SDK/外部程序。项目文件、独立分叉、临时输出、远端副本、系统备份不删除；文件系统删除不是物理安全擦除。没有进行真实断电测试。

## 开发验证

```bash
pnpm check
pnpm test
pnpm test:integration
```

单元测试覆盖删除/GC 范围隔离、子代理及分叉、共享/草稿/路径引用、损坏输入、事务中断、宿主终止、并发屏障和浏览器草稿保护。真实 DSH + Chrome 集成使用独立临时数据目录：另一会话持续维护时删除、并行输入上传、目标跨标签锁、原生菜单、独立 GC 的准入与排队，以及故障后的删除标记和重启。测试不调用模型，不删除真实用户会话，也不对真实数据执行 GC。

归档与销毁的上游证据见 `UPSTREAM_AUDIT.md`；`REVIEW.md` 是 **0.2.1 的历史独立审阅**，不构成对当前版本的新独立审阅认证。当前测试与安装摘要见 `validation.json`。
